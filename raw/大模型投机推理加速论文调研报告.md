## 二、核心方法改进

### 2.1 SMART: 硬件感知的投机树扩展决策 [2604.09731]

**链接**: [https://arxiv.org/abs/2604.09731](https://arxiv.org/abs/2604.09731)

**作者**: Lifu Wang, Pan Zhou

**解决的问题——效率悖论**: 现有树形投机解码盲目追求最大化接受 token 数，忽略了大树的构建和验证开销会超线性增长。尤其在 batch size 增大或硬件饱和时，反而导致负的 wall-clock 加速比。

**方法**:

- 将树扩展建模为**硬件感知的端到端加速比优化问题**
    
- 边际效益-成本原则：仅当节点的边际收益/成本比超过当前树的加速比时才扩展该节点
    
- **训练免费、即插即用**，可作为 MSD/EAGLE 等框架的控制器
    

**关键结果**:

- 在 3 个 MLLM 和 4 个 LLM 上，MLLM 额外加速 **20.0%**，LLM 额外加速 **15.4%**
    
- 跨不同 GPU 架构均有效，无性能损失
    

---

### 2.2 Goose: 各向异性投机树 [2604.02047]

**链接**: [https://arxiv.org/abs/2604.02047](https://arxiv.org/abs/2604.02047)

**作者**: Tao Jin, Phuong Minh Nguyen, Naoya Inoue

**解决的问题**: 现有训练免费方法的树结构是平衡的（深度=广度），但不同来源的候选 token 质量差异巨大（n-gram 匹配接受率比统计预测高 **6 倍中位数差距**），平衡树受限于深度上限。

**方法**:

- **各向异性（非对称）树结构**：高质量 token 形成深链，低质量 token 展开宽分支
    
- 自适应脊柱树：context-matched 的高接受率 token 构成深层主干，每个节点挂低接受率的宽分支
    
- **理论证明**接受 token 数不少于任一源单独使用
    

**关键结果**:

- 在 5 个 LLM (7B-33B) 和 5 个 benchmark 上实现 **1.9-4.3x** 无损加速
    
- 比平衡树基线提升 **12-33%**

### 2.3 DIVERSED: 动态集成松弛验证 [2604.07622]

**链接**: [https://arxiv.org/abs/2604.07622](https://arxiv.org/abs/2604.07622)

**作者**: Ziyi Wang, Siva Rajesh Kasa, Ankith M S, Santhosh Kumar Kasa, Jiaru Zou, Sumit Negi, Ruqi Zhang 等

**解决的问题**: 现有投机解码的验证步骤过于严格，要求接受 token 分布必须与目标模型完全一致，导致大量合理 token 被拒，接受率低。

**方法**:

- **动态集成验证器**：将草稿模型和目标模型分布按任务和上下文自适应加权混合
    
- 放松分布匹配约束，提高接受率同时保持生成质量
    
- 提供理论证明
    

**关键结果**:

- 相比标准投机解码显著提升推理效率，有开源代码

### 2.4 Cactus: 约束接受投机采样 [2604.04987]

**链接**: [https://arxiv.org/abs/2604.04987](https://arxiv.org/abs/2604.04987)

**作者**: Yongchang Hao, Lili Mou

**解决的问题**: 标准投机采样严格要求生成分布与验证器完全一致（top-k、temperature 变换也可接受）。典型接受采样 (TAS) 虽能提高接受率但会扭曲验证器分布，降低输出质量。

**方法**:

- 从**约束优化视角**形式化投机采样算法
    
- Cactus 保证与验证器分布的发散度**可控**，同时提高接受率
    
- 数学上有严格的理论保证
    

**关键结果**:

- 在多个 benchmark 上验证有效性

### 2.5 MetaSD: 多草稿协作投机解码 [2604.05417]

**链接**: [https://arxiv.org/abs/2604.05417](https://arxiv.org/abs/2604.05417)

**作者**: Taehyeon Kim, Hojung Jung, Se-Young Yun

**解决的问题**: 单一草稿模型通常针对特定任务/领域训练，在多场景下效果有限。

**方法**:

- 整合**多个异构草稿模型**到投机解码流程
    
- 利用**对齐反馈**动态分配计算资源给不同草稿
    
- 将草稿选择建模为**多臂老虎机问题**
    

**关键结果**:

- 跨多个实验一致优于单一草稿方法

### 2.6 SpecMoE: MoE 自辅助投机解码 [2604.10152]

**链接**: [https://arxiv.org/abs/2604.10152](https://arxiv.org/abs/2604.10152)

**作者**: Jehyeon Bang, Eunyeong Cho, Ranggi Hwang, Jinha Chung, Minsoo Rhu

**解决的问题**: MoE 架构内存需求高、参数效率低，CPU offload 方案在大 batch size 下效率有限。

**方法**:

- 将投机解码应用于 MoE 推理，**无需额外训练或微调**
    
- **自辅助投机解码**：利用 MoE 自身结构进行草稿和验证
    
- 显著降低内存和互联带宽需求
    

**关键结果**:

- 在内存受限系统上推理吞吐量提升最高 **4.30x**

## 三、扩散模型投机解码

### 3.1 S2D2: 训练自由的扩散 LLM 自投机 [2603.25702]

**链接**: [https://arxiv.org/abs/2603.25702](https://arxiv.org/abs/2603.25702)

**作者**: Ligong Han, Hao Wang, Han Gao, Kai Xu, Akash Srivastava

**解决的问题**: Block-diffusion 语言模型在少步解码时，标准置信度阈值策略脆弱：激进的阈值损质量，保守的阈值浪费步数。现有方法需要额外训练或增加测试时计算。

**方法**:

- **训练免费自投机框架**
    
- 核心洞察：block-size=1 时 block-diffusion 退化为 AR，**同一预训练模型可自充当草稿和验证器**
    
- 插入投机验证步到标准解码流程，轻量路由策略决定是否值得验证代价
    
- 混合解码轨迹：扩散并行生成，AR 模式作为局部 critic
    

**关键结果**:

- SDAR 上最高 **4.7x** 加速 vs AR，**1.57x** 加速 vs 动态解码基线，精度提升 **4.5 点**
    
- LLaDA2.1-Mini 上 **4.4x** 加速，略高于基线精度
    
- 兼容内置自校正机制

### 3.2 DualDiffusion: 掩码扩散模型投机解码 [2604.05250]

**链接**: [https://arxiv.org/abs/2604.05250](https://arxiv.org/abs/2604.05250)

**作者**: Satyam Goyal, Kushal Patel, Tanush Mittal, Arjun Laxman

**解决的问题**: Masked Diffusion Models 因双向注意力无法缓存 KV pair，每步需 O(N^2) 计算。现有加速方法 (FastDLLM, DkvCache) 以损失生成质量为代价。

**方法**:

- 投机解码框架：**快速草稿模型**（高效近似）+ **慢速精确验证器**
    
- 草稿模型跑多步 lightweight 推导，单次验证器验证
    
- 在 Pareto frontier 上超越现有方法
    

**关键结果**:

- MMLU 和 GSM8K 上保持高精度同时减少生成步数

## 四、Video-LLM 投机解码

### 4.1 ParallelVLM: 视觉对齐感知并行投机解码 [2603.19610]

**链接**: [https://arxiv.org/abs/2603.19610](https://arxiv.org/abs/2603.19610)

**作者**: Quan Kong, Yuhao Shen, Yicheng Ji, Huan Li, Cong Wang

**解决的问题**: Video-LLM 自回归解码受海量 video token 限制。现有 token pruning 方法有信息损失，加速效果有限。草稿与目标模型之间存在互等互待问题。

**方法**:

- **训练免费** draft-then-verify 框架
    
- 两个**并行阶段**最大化硬件利用率，消除互等互待
    
- Unbiased Verifier-Guided Pruning：消除注意力引导剪枝中的位置偏差
    

**关键结果**:

- 草稿窗口扩大 **1.6-1.8x**，接受长度高
    
- LLaVA-OneVision-72B 加速 **3.36x**
    
- Qwen2.5-VL-32B 加速 **2.42x**

### 4.2 LVSpec: 松散投机解码 for Video LLMs [2604.05650]

**链接**: [https://arxiv.org/abs/2604.05650](https://arxiv.org/abs/2604.05650)

**作者**: Yicheng Ji, Jun Zhang, Jinpeng Chen, Cong Wang, Lidan Shou, Gang Chen, Huan Li

**解决的问题**: 现有 Video-LLM 投机解码受限于严格的 exact-match 规则，加速潜力受限。

**方法**:

- 首个**训练免费松散投机解码框架**
    
- 洞察：生成由稀疏视觉相关 anchor（需严格验证）和大量视觉无关 filler（可松散验证）共同驱动
    
- 轻量识别方案 pinpoint 视觉相关 token
    
- **位置偏移容忍机制**：挽救位置不同但语义等价的 token
    

**关键结果**:

- 保持 **>99.8%** 目标性能
    
- Qwen2.5-VL-32B 加速 **2.70x**，LLaVA-OneVision-72B 加速 **2.94x**
    
- 平均接受长度提升 **136%**，加速比提升 **35%** vs SOTA 训练免费方法

## 五、代替投机解码的多 Token 生成

### 5.1 MARS: 屏蔽自回归多 Token 生成 [2604.07023]

**链接**: [https://arxiv.org/abs/2604.07023](https://arxiv.org/abs/2604.07023)

**作者**: Ziqi Jin, Lei Wang, Ziwei Luo, Aixin Sun

**解决的问题**: AR 模型逐 token 生成，即使连续 token 高度可预测。投机解码需维护草稿模型，Medusa 等多头方法需额外参数。

**方法**:

- 轻量微调：教 AR 模型**每步预测多 token**
    
- **无架构改动，无额外参数**，生成单一模型
    
- 无需额外训练数据，仅用已有指令数据继续训练
    
- Block-level KV caching 策略支持批量推理
    
- 置信度阈值支持**实时速度调节**（高负载时可即时调整）
    

**关键结果**:

- 单 token/步时性能持平或超越基线
    
- 多 token/步时保持精度，吞吐量 **1.5-1.7x**
    
- Qwen2.5-7B 上 wall-clock 加速 **1.71x**

## 六、Block-Diffusion VLM

### 6.1 Fast-dVLM: 块扩散视觉语言模型 [2604.06832]

**链接**: [https://arxiv.org/abs/2604.06832](https://arxiv.org/abs/2604.06832)

**作者**: Chengyue Wu, Shiyi Lan, Yonggan Fu, Sensen Gao, Jin Wang, Jincheng Yu, Jose M. Alvarez 等

**解决的问题**: VLM 自回归逐 token 生成限制吞吐量，在机器人/自动驾驶等 edge 场景 batch-size=1 下受内存带宽限制。

**方法**:

- Block-diffusion VLM：KV-cache 兼容的**并行解码 + 投机块解码**
    
- 系统比较两种 AR-to-diffusion 转换：两阶段（先文本后多模态）vs **直接转换**（全模型一步）
    
- 直接转换更高效：利用已多模态对齐的 VLM
    
- 引入多模态扩散适配：块大小退火、因果上下文注意力、自截断掩码、视觉高效拼接
    

**关键结果**:

- 11 个多模态 benchmark 上质量与 AR 对标
    
- SGLang + FP8 量化下端到端加速 **>6x**

## 七、混合 AR-Diffusion 视觉生成

### 7.1 Drift-AR: 反对称漂移单步视觉生成 [2603.28049]

**链接**: [https://arxiv.org/abs/2603.28049](https://arxiv.org/abs/2603.28049)

**作者**: Zhen Zou, Xiaoxiao Ma, Mingde Yao, Jie Huang, LinJiang Huang, Feng Zhao

**解决的问题**: AR-Diffusion 混合范式存在**双速瓶颈**：AR 阶段串行 + 扩散视觉解码迭代多步去噪。现有方法分别优化，缺乏统一原则。

**方法**:

- 统一信号：每个位置的**预测熵**编码空间变化的生成不确定性
    
- AR 加速：**Entropy-Informed Speculative Decoding**，通过因果归一化熵损失对齐草稿-目标熵分布，解决熵失配导致的草稿过高拒率
    
- 视觉解码加速：将熵重新解释为**反对称漂移场的物理方差**——高熵位置强漂移，低熵位置无漂移——实现**单步 (1-NFE) 解码**
    
- 两阶段共享同一熵信号，无额外计算成本
    

**关键结果**:

- MAR, TransDiff, NextStep-1 上 **3.8-5.5x** 加速
    
- 单步解码质量持平或超越原始，无需蒸馏

## 八、投机 Jacobi 解码（图像生成）

### 8.1 SJD-VP: 投机 Jacobi 解码与验证预测 [2603.27115]

**链接**: [https://arxiv.org/abs/2603.27115](https://arxiv.org/abs/2603.27115)

**作者**: Bingqi Shan, Baoquan Zhang, Xiaochen Qi, Xutao Li, Yunming Ye, Liqiang Nie

**解决的问题**: 投机 Jacobi 解码 (SJD) 加速自回归图像生成，但投机 token 接受率低（因 token 选择模糊）。现有方法主要从宽松验证角度改进，**未充分挖掘迭代的动态特性**。

**方法**:

- 新洞察：**迭代间概率增加的 token 更可能通过后续验证且正确**
    
- 利用跨迭代 token 概率变化指导采样，偏好概率增长的 token
    
- 有效预测哪些 token 能通过后续验证，提高接受率
    
- **即插即用**，可无缝集成到现有 SJD 方法中
    

**关键结果**:

- 标准 benchmark 上一致加速自回归解码，同时**提升图像生成质量**

## 九、分布式系统与硬件优化

### 9.1 ConfigSpec: 边缘云投机 LLM 服务配置选择 [2604.09722]

**链接**: [https://arxiv.org/abs/2604.09722](https://arxiv.org/abs/2604.09722)

**作者**: Xiangchen Li, Saeid Ghafouri, Jiakun Fan, Babar Ali, Hans Vandierendonck, Dimitrios S. Nikolopoulos

**解决的问题**: 投机解码的边缘云部署面临庞大配置空间（草稿模型变体、量化级别、投机长度、异构设备），**无单一配置能同时优化所有目标**。

**方法**:

- 剖析设备性能和草稿-目标对齐度
    
- 建模草稿吞吐量、接受率和功耗
    
- 评估 goodput、验证成本效率和能效
    
- **联合配置空间搜索**
    

**关键结果**:

- 3 个 edge 平台和 2 个 LLM 家族上发现**结构性冲突最优**：
    
    - **Goodput**：最小最快草稿模型在设备相关长度 K*=2~10 最大化
        
    - **能效和成本效率**均收敛于 K=2（bonus-token 效应）
        
    - 成本偏好最大草稿（高接受率），能效偏好最小草稿（低功耗）
        
- 确认**无单一固定配置**能同时优化所有目标

### 9.2 A-IO: 内存受限 NPU 的自适应推理编排 [2604.09752]

**链接**: [https://arxiv.org/abs/2604.09752](https://arxiv.org/abs/2604.09752)

**作者**: Chen Zhang, Yan Ding, Haotian Wang, Chubo Liu, Keqin Li, Kenli Li

**解决的问题**: LLM 在异构 NPU 上自回归解码阶段受严重内存瓶颈限制。发现静态部署单一尺寸模型导致**"模型扩展悖论"**，且细粒度投机解码在 NPU 计算图编译下有核同步开销，Prompt LookUp Decoding 等微观加速手段受限。

**方法**:

- 自适应推理编排：根据 NPU 内存特性和计算图编译特性动态调度
    

**关键结果**:

- 在 Ascend 910B 等 NPU 平台上的系统性优化分析

## 十、研究趋势总结

### 10.1 八大研究方向

| 趋势方向              | 核心思想                    | 代表论文                                     |
| ----------------- | ----------------------- | ---------------------------------------- |
| **放宽验证约束**        | 不要求严格分布匹配，在质量可控前提下提高接受率 | DIVERSED, Cactus, LVSpec                 |
| **树结构优化**         | 硬件感知边际分析和各向异性树，突破平衡树限制  | SMART, Goose                             |
| **多草稿协作**         | 多模型集成，动态分配资源            | MetaSD                                   |
| **自投机（无额外模型）**    | 同一模型同时充当草稿和验证器          | SpecMoE, S2D2                            |
| **扩散模型加速**        | 将投机解码思想从 AR 扩展到扩散/块扩散模型 | S2D2, DualDiffusion, Fast-dVLM, Drift-AR |
| **多模态/Video-LLM** | 视觉引导的松散投机和视频场景并行解码      | ParallelVLM, LVSpec, Fast-dVLM           |
| **系统级优化**         | 端到端视角，考虑硬件、网络、能耗        | ConfigSpec, A-IO, SMART                  |
| **图像生成投机**        | 利用迭代动态的投机 Jacobi 解码     | SJD-VP                                   |

### 10.2 关键趋势洞察

**1. "松弛化"成为主流方向**

多篇论文（DIVERSED, Cactus, LVSpec, SJD-VP）都在放宽传统的严格验证规则——从完全分布匹配放宽到可控发散、从 exact-match 放宽到语义等价匹配。核心共识：严格匹配是不必要的冗余约束。

**2. 树结构从"平衡"到"各向异性"**

SMART 和 Goose 打破了"越大越好"的误区——SMART 证明大树在硬件约束下可能负加速，Goose 证明不同质量源应分配不同的树结构。

**3. "自投机"消除额外开销**

SpecMoE, S2D2 展示了无需额外草稿模型的自投机方案，消除了额外模型的存储和计算开销。MARS 则走向更激进的路线——直接让原模型输出多 token。

**4. 投机思想向非 AR 架构扩散**

从最初的 AR LLM，投机解码已扩展到：MoE (SpecMoE)、Masked Diffusion (DualDiffusion)、Block-Diffusion (S2D2)、Video-LLM (ParallelVLM, LVSpec)、图像生成 (SJD-VP)。

**5. 系统视角日益重要**

ConfigSpec 和 A-IO 表明，单纯追求算法加速不够，必须在端到端系统层面考虑硬件约束、配置选择和能耗。SMART 也从算法方法走向系统-aware 方法。
