## 一、投机解码（Spec Decode）—— 本期最密集主线

业界共识：投机解码是当前 decode 阶段提吞吐/降延迟的头号抓手。本期三大引擎同时在「框架化 + 算子融合 + 通信削减」三个层面发力。

| 引擎 | 关键特性 | 解决的问题 | 方案 | 效果 |
|------|----------|-----------|------|------|
| **sglang** | **Spec V2 体系化、弃用 V1**（#25464） | V1 投机解码代码分散、tree drafting 受限 | 统一 `spec_utils`，token resolver 重写为 `_resolve_spec_v2_tokens`，清理死代码 | 投机路径收敛为单一可维护体系 |
| **sglang** | **Spec v2 tree drafting（topk>1）支持 page_size>1**（#26972） | 树状草稿此前只在 page_size=1 可用 | 扩展 draft KV 索引与 page_table scatter 到 topk>1+page>1 | 大页 + 多分支草稿可同时启用，命中率↑ |
| **sglang** | **ngram spec v2**（#17260）；`gather_spec_extras` 小核融合（#27233） | n-gram 草稿与小算子启动开销 | 融合 draft 相关小 kernel | 减少 kernel launch，draft 阶段提速 |
| **vllm** | **大词表 draft 模型减少 TP 通信**（#39419） | 大 vocab draft 在 TP 下 all-reduce 通信量大 | 优化草稿采样的 TP 通信路径 | 降低投机解码的多卡通信开销 |
| **vllm** | **Model Runner V2 + DFlash / Gemma4 MTP**（#44586 #43241） | MRV2 下投机与 MTP 适配 | MRV2 接入 DFlash、Gemma4 MTP，speculator prefill 不同注意力态预热捕获 | 新调度栈下投机解码可用 |
| **tokenspeed** | **DSv4 MTP 前缀缓存复用**（#361）；draft catch-up 跳过死位计算（#217） | MTP 重复 prefill、草稿追赶冗余计算 | MTP 复用前缀缓存，decode 草稿追赶跳过 dead-position | 减少 MTP 重算与无效计算 |
| **vllm-ascend** | **Magic MTP 修复 + Entropy Verify**（#9772）；pcp/dcp+spec 的不规则 mask 构建（#9678） | 昇腾侧 MTP 精度 + 并行下投机 mask | 加入熵校验、irregular mask build | 昇腾投机解码精度与并行兼容 |

**小结**：投机解码正从「能跑」走向「框架统一（V2）+ 大页树草稿 + 通信/算子双削减」，是本期跨引擎对齐度最高的方向。

## 二、CUDA Graph / 图捕获 —— 消除调度与启动开销

问题：decode 阶段单步算子多、Python/launch 开销占比高；动态 batch size 与投机/混合模型让全图捕获困难。

- **sglang — CUDA Graph Runner/Backend 重构**（#23906）：把图捕获后端抽象化；eager forward 路径也走 **CUDA graph input-buffer registry**（#27407），统一缓冲区管理。
- **sglang — Piecewise CUDA Graph**：dflash 支持 piecewise cuda graph（#27468）；AMD 启用 piecewise（#22299）；`piecewise_cuda_graph_max_tokens` 按 context length 钳制（#22516）。**解决：全图捕获在长上下文/混合算子下不可行，分段捕获兼顾覆盖率与灵活性。**
- **sglang — Breakable CUDA Graph for DSv4 DP attention**（#25195，BCG）：DP attention 下图可断，适配稀疏注意力。
- **vllm — ViT 全 CUDA graph**（#40576 #44484）：glm4_1v 图文/视频推理的视觉塔走全图，多模态 prefill 提速。
- **vllm-ascend — npugraph_ex 冷启动编译缓存**（#9914）、**KV cache 分配前预估 ACL graph 显存**（#9865）：昇腾图模式的启动与显存规划。

## 四、MoE / 量化（FP8 / FP4 / MXFP）—— 大模型主力算力

- **vllm — fused_moe FP8 配置调优**（#44830）：Qwen3-Next-80B tp=4 @H100，**batch 96-512 区间 +25%**（自带数字）。
- **vllm — online fp8 ptpc**（#44132）、FP8 权重布局源头规范为 (K,N)（#44735）；ROCm 融合 **AR + RMSNorm + per-group FP8 quant**（#42864）。
- **sglang — online nvfp4 量化**（#26083）、Gemma4 NVFP4 MoE 默认注意力后端修复（#26791）；DSv4 decode 去掉冗余 fp8 scale 转置拷贝（#27289，ROCm）；修 fp16 模型 FP8 gemm 性能（#22300）。
- **vllm — MoE/MoERunner 反转重构**（#41184）：MoE 执行层解耦，便于多后端（CPU/CUTLASS/Triton）接入。

**趋势**：量化精度下探到 **FP4/NVFP4/MXFP4**，且把 **AllReduce+Norm+Quant 三件套融合**成为降通信+降访存的标准手法。

## 结论：近期推理性能优化的「底层逻辑」

1. **decode 提速看投机解码** —— 本期最集中，方向是框架统一（Spec V2）+ 大页树草稿 + 通信/算子双削减。
2. **launch/调度开销看 CUDA Graph** —— 从全图走向 **piecewise / breakable**，覆盖长上下文与混合/稀疏模型。
3. **算力密度看量化下探** —— FP4/NVFP4/MXFP4 + **AR+Norm+Quant 融合**。
4. **新模型驱动专用核** —— MLA、GDN（线性注意力）、稀疏注意力（DSA/KDA）各自出专用 prefill/decode kernel，Blackwell(SM100/SM120) 是新核首发平台。
5. **阶段解耦看 PD 异构** —— prefill/decode 不仅分离，还开始**异构 TP** 按阶段配比算力。

> 可延伸专题：① sglang Spec V2 vs vllm MRV2 spec 的实现对比；② piecewise/breakable CUDA graph 在混合模型下的捕获策略对比；③ MLA decode kernel 在 vllm / sglang / tokenspeed 三家的实现与性能差异。
