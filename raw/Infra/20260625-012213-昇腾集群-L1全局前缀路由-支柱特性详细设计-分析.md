## 0. 一句话设计

> agentic 多轮的命门是"历史 KV 在哪个实例、请求能否路由过去命中"。**vllm 已有全部底层原语**（connector ABI + KV 事件 + 可换 proxy），L1 要构建的只是把它们串成"全局前缀索引 + prefix-affinity 路由"的**编排层**——属 A 层（官方扩展点），近零 patch。

## 1. 已坐实的挂载面（L1 不用造轮子）

| 原语 | 作用 | 证据 |
|------|------|------|
| `KVConnectorBase_V1` 抽象基类 | 版本稳定的扩展点契约 | base.py:171 |
| `get_num_new_matched_tokens(request, num_computed_tokens)` | **调度时返回"外部已匹配 token 数"** = 命中查询入口 | base.py:454；mooncake_connector.py:1284 |
| `update_state_after_alloc` | 命中块注册到请求 | base.py（抽象）；mooncake_connector.py:1288 |
| `build_connector_meta` | 把命中决策传给 worker | base.py:510 |
| `request_finished` / `request_finished_all_groups` | 请求结束时上报持有的 block | base.py:542；mooncake_connector.py:1316 |

> **关键**：全局索引的"事件源"`KVCacheEvent` 已存在（dynamo 的 KVPublisher 同款思路），L1 无需自建事件总线——**消费现有 kv_events 即可**。

## 2. L1 三层架构（要构建的部分）

```
┌────────────────────────────────────────────────────────┐
│  ① Prefix-Affinity Proxy（替换 round-robin）            │
│     输入：请求 prompt → 算 block_hash 前缀              │
│     查全局索引 → 得"命中最多的实例 + 负载" → 联合决策  │
│     落点：fork examples/.../load_balance_proxy_server   │
├────────────────────────────────────────────────────────┤
│  ② Global Prefix Index（新建，无状态可重建服务）        │
│     数据源：各实例 KVCacheEvent (stored/removed)        │
│     结构：全局 Radix/前缀树，叶=（block_hash→实例集合） │
│     查询：prefix → 持有实例 + 命中长度                  │
├────────────────────────────────────────────────────────┤
│  ③ Connector 侧命中上报（复用现有钩子，零改）           │
│     get_num_new_matched_tokens → 命中查询               │
│     request_finished → 上报持有 block                   │
│     register_kv_caches → worker KV 注册                 │
└────────────────────────────────────────────────────────┘
```

## 3. 切入点与改动面（A 层，可迁移性核算）

| 组件 | 改动方式 | patch 面积 |
|------|---------|-----------|
| ③ 命中上报 | **复用现有 connector 钩子**，不改源码 | 0 |
| ② 全局索引 | **新建独立服务**（消费 kv_events），不在 vllm 进程内 | 0（外部进程） |
| ① proxy | **fork example proxy**（本就是示例，非核心） | 0 核心 patch |

> **结论**：L1 整体 **净新增 patch 文件 = 0**，完全落在 A 层官方扩展点 + 外部服务。这是它"可迁移性最优"的根因——上游升级只要 `KVConnectorBase_V1` ABI 与 `kv_events` 不变（二者是稳定公共 API），L1 零感知。

## 4. 路由决策：prefix-affinity × load 联合（避免热点）

借鉴 dynamo KV Router 代价函数思路（[[20260608-004619-all-repos-kvcache与调度优化-分析]] 已分析），昇腾侧落地：

```
cost(instance) = α·(new_prefill_tokens − overlap_hit·hit_credit)
                 + β·decode_load(instance)
选 cost 最小实例；softmax 温度调"命中优先 vs 负载均衡"
  • 高 hit_credit → 偏命中复用（降 TTFT，agentic 友好）
  • 高 β → 偏均衡（防热点把请求都压到持有长前缀的实例）
```

## 5. 命中率推导（与主文档 §3.5.3 一致）

```
agentic 多轮：命中率 = H/(H+x)，H=历史累积，x=单轮新增
有全局索引：历史 KV 即使在别的实例也能被路由命中 → 接近理论 77%
无全局索引（仅实例内 Radix）：命中率 = 历史恰好落在同实例的概率
  ≈ 1/实例数（round-robin 下） → 大规模集群下趋近 0
```

> **L1 的价值量化**：把命中率从"≈1/N（N=实例数）"拉到"≈77%（场景理论值）"。N 越大、轮次越多，L1 收益越大——正是大规模 agentic 集群的命门。

## 6. 遗留问题（要求 1）

1. **全局索引一致性 vs 开销**：KVCacheEvent 上报有延迟，索引可能短暂 stale → 路由到已 evict 的实例。需 TTL/版本号，开销无代码可算。❓
2. **block_hash 跨实例一致性**：proxy 侧算的 hash 必须与 worker 侧 `register_kv_caches` 的 hash 同源，否则查不中。需确认 vllm block hash 算法可在 proxy 侧复现。❓
3. **命中率 77% 是场景理论值**，真实多轮分布（H/x 比例）依业务，须 E3 实验（主文档 §7）实测。❓
4. **全局索引服务的容错**：索引服务挂了路由退化到 round-robin（可接受），但恢复期命中率掉底。属可接受降级，需验证。🟡

## 7. 与主文档验证矩阵的衔接

L1 对应主文档 §7 的 **E3 实验**（multi_turn benchmark，轮次扫描，external_prefix_cache_hits 算命中率）。单节点先测实例内 Radix 命中下界；全局索引跨实例增量需多节点外推。
