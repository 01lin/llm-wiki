## 0. 结论先行（一句话）

> **DBO（vllm 上游 `enable_dbo`/ubatch 机制）在 vllm-ascend 上不支持——被 platform 层强制关闭，与模型、硬件无关。** 但 vllm-ascend 有**自己的 NPU 原生多流重叠**（multistream_*，含 DeepSeek-V4-DSA 专属的 `multistream_dsv4_dsa_overlap`），那才是 NPU 上真实可用的"计算通信重叠"等价物。**问 DBO 是否支持 V4+910B3：DBO 本身不支持（被关）；但同类目标由 NPU 多流重叠达成，且 V4 有专属路径。**

---

## 1. DBO 是什么（上游语义）

DBO = Dual-Batch Overlap：把一个 batch 拆成 2 个微批（micro-batch / ubatch），用微批 A 的 MoE all-to-all **通信**与微批 B 的**计算**重叠，隐藏大规模 EP 下的通信开销。

上游 vllm 实现：
- 配置：`enable_dbo: bool = False`（vllm config/parallel.py:208），`num_ubatches=2 if enable_dbo`（:520）。
- 执行：`maybe_create_ubatch_slices(should_ubatch, ...)`（vllm ubatch_utils.py:63）——`should_ubatch=False` 时返回 `(None, None)`（:71-72），即不拆微批。

## 2. 判定一：DBO 在 vllm-ascend 被**强制关闭**（决定性证据）

**vllm-ascend/vllm_ascend/platform.py:1175-1188**（platform 初始化期）：
```python
if getattr(vllm_config.parallel_config, "enable_dbo", False):
    logger.warning(
        "Parameter is currently ignored on Ascend. parameter=enable_dbo, action: resetting to False. "
    )
    vllm_config.parallel_config.enable_dbo = False          # ← 强制关

ubatch_size = getattr(vllm_config.parallel_config, "ubatch_size", 0)
if ubatch_size != 0:
    ... "parameter=ubatch_size, ... resetting to 0."
    vllm_config.parallel_config.ubatch_size = 0             # ← 另一入口也关
```

> **结论**：无论用户怎么配 `--enable-dbo` 或 `ubatch_size`，vllm-ascend 在 platform 层**一律重置为 False/0**，并打印 "currently ignored on Ascend"。**DBO 在昇腾上根本不会生效**，与模型/硬件无关。

**佐证（DBO 路径全是死路）**：
- `should_ubatch` 在 `_determine_batch_execution_and_padding` 初始化为 `False`（model_runner_v1.py:2905），**函数体内从未被设为 True**（grep 全文件确认）。
- dummy_run 路径显式注释：**"vllm-ascend does not support ubatch now"**（model_runner_v1.py:3403-3404），`ubatch_slices = None`。
- `enable_dbo` 仅作为构造参数传给 `AscendMoERunner`（fused_moe.py:478）与 `_310p`（:187）——因上游值恒为 False，**该参数恒为 False，分支永不进**。
- mla_v1.py:1777 只是一条注释（"should be ... in dbo"），非执行。

## 3. 判定二：NPU 原生多流重叠才是真实可用（DeepSeek-V4 有专属路径）

DBO 虽不支持，但 vllm-ascend **自己实现了 NPU 多流重叠**（用 `npu_stream_switch` 切第二条 stream 做重叠），这是真实执行的代码：

| 多流杠杆 | 真实执行证据 | 作用域 |
|---------|------------|-------|
| shared-expert 重叠 | `with npu_stream_switch(shared_experts_calculation_stream(), enabled=self.multistream_overlap_shared_expert)`（fused_moe.py:748） | MoE 共享专家与路由专家重叠 |
| gate 重叠 | `with npu_stream_switch(AscendFusedMoE.gate_stream, ...)`（fused_moe.py:624） | gate 计算重叠 |
| **DSV4 DSA 重叠** | `if self.multistream_dsv4_dsa_overlap`（dsa_v1.py:1494）+ `aux_stream = dsv4_dsa_overlap_stream()` + `npu_stream_switch(aux_stream, ...)` | **DeepSeek-V4 DSA 稀疏注意力专属双流** |
| prefill 通信计算重叠 | `prefill_comm_compute_overlap`（dsa_v1.py:1440/1595，delay allgather 优化） | prefill 阶段 |

> **关键**：`multistream_dsv4_dsa_overlap`（dsa_v1.py:1439/1494，名字即含 dsv4）**专为 DeepSeek-V4 的 DSA 稀疏注意力设计**，有 aux-stream warmup 保证 ACL graph 兼容（dsa_v1.py:1490 注释）。**与 dsv4_dsa_overlap 互斥的是 prefill_comm_compute_overlap（dsa_v1.py:1598 注释"multistream wins"）**。

## 4. DeepSeek-V4-Flash + 910B3 适配性逐项判定

**DeepSeek-V4-Flash HF config 实测**（huggingface.co/deepseek-ai/DeepSeek-V4-Flash）：
- `model_type=deepseek_v4`，`architectures=[DeepseekV4ForCausalLM]`
- `num_hidden_layers=43`，`n_routed_experts=256`，`num_experts_per_tok=6`，`n_shared_experts=1`（→ 有 shared expert，multistream_overlap_shared_expert 适用）
- `head_dim=512`（MLA latent），`qk_rope_head_dim=64`，`index_topk=512`，`index_head_dim=128`，`sliding_window=128`
- `compress_ratios=[0,0,4,128,4,128...]`（逐层：0=不压缩，4/128=压缩档，含 SWA）

| 维度 | DBO（上游） | NPU 多流重叠（vllm-ascend 原生） |
|------|-----------|-------------------------------|
| **是否支持** | ❌ 否（platform 强制关，:1179） | ✅ 是（npu_stream_switch 真实执行） |
| **DeepSeek-V4 适配** | N/A（全局被关） | ✅ V4 走 `DeepseekV4MoE`(deepseek_v4.py:354)→`FusedMoE`→`AscendMoERunner`；DSA 走 `multistream_dsv4_dsa_overlap`（V4 专属） |
| **shared-expert 重叠** | N/A | ✅ V4 有 n_shared_experts=1，条件 `has_shared_experts`(fused_moe.py:386) 满足 |
| **910B3 硬件** | N/A | ✅ fused_moe/dsa 多流路径**未见 910 代际门控**（不限 A2/A3/A5），910B3 适用 |
| **默认状态** | 强制 False | 默认 False（additional_config，需手动开） |
| **bf16 兼容** | N/A | ✅ 纯 stream 调度，与精度无关 |

> **逐项结论**：
> 1. **DBO 本身**：DeepSeek-V4 + 910B3 **不支持**（不是 V4/910B3 的问题，是 vllm-ascend 全局关 DBO）。
> 2. **等价能力（NPU 多流重叠）**：**支持** DeepSeek-V4 + 910B3，且 V4 有 DSA 专属重叠路径 `multistream_dsv4_dsa_overlap`。
> 3. **910B3 硬件门控**：在 fused_moe/dsa 多流代码层**未发现代际限制**——但需注意 ACL graph 兼容性（dsa_v1.py:1490 有 aux-stream warmup 处理）。

## 5. 修正前序文档的错误结论（诚实纠错）

> **倍率总账影响**：因 1.5–1.7× 本就主要靠多流重叠（DBO 在弱带宽 NPU 上的增量有限），**修正归因后 5–10× 合成数值不变**（L2' 多流仍提供 1.5–1.7×），但**机制描述从"DBO+多流"更正为"纯 NPU 多流重叠"**。这是 GPU 特性误判为 NPU 的典型纠错。

1. **多流重叠各路收益占比** — shared-expert/gate/DSV4-DSA/prefill 四路真实增益无昇腾实测，需 E1（已改为多流对比）实测。❓
2. **910B3 上 ACL graph × 多流兼容性** — dsa_v1.py:1490 有 aux-stream warmup，但实际 graph 捕获覆盖率需验证。❓
3. **multistream 互斥约束** — `multistream_dsv4_dsa_overlap` 与 `prefill_comm_compute_overlap` 互斥（dsa_v1.py:1598）；`multistream_overlap_shared_expert` 与 `enable_shared_expert_dp`/Mix placement 互斥（ascend_config.py:300）。组合启用需避坑。✅ 已坐实

## 7. 给方案的直接结论

- **不要在 recipe 里配 `--enable-dbo`**（无效，会被重置 + 打 warning）。
- **要配 NPU 多流重叠**（bf16，DeepSeek-V4+910B3 真实支持）：
  ```bash
  --additional-config '{"multistream_dsv4_dsa_overlap":true,
                        "multistream_overlap_shared_expert":true,
                        "multistream_overlap_gate":true}'
  # 注意：prefill_comm_compute_overlap 与 dsv4_dsa_overlap 互斥，二选一
  # 注意：multistream_overlap_shared_expert 与 enable_shared_expert_dp 互斥
  ```
- **L2 杠杆的正确名称应为"NPU 多流重叠"而非"DBO"**——全语料据此归因更正。

> 多流开关的互斥关系、场景 recipe、算子级遮掩图解见 [[20260625-134130-昇腾NPU-deepseek-v4多流遮掩特性-互斥关系与场景recipe-分析]]。
