## 0. 实现总览（三条红线贯穿）

| 红线 | 实现层落实 |
|------|-----------|
| **异步遮掩兼容** | `k_active` 是 CPU 标量，不进任何 stream/event 等待；沿用现有 [valid_sampled_token_count 独立 stream + non_blocking + event](file:///Users/linyi/code/Documents/code/vllm-ascend/vllm_ascend/worker/model_runner_v1.py) 范式 |
| **精度不变** | padding 用 [PLACEHOLDER_TOKEN_ID](file:///Users/linyi/code/Documents/code/vllm/vllm/v1/sample/rejection_sampler.py)，rejection sampler 用 per-req [num_draft_tokens=k_active](file:///Users/linyi/code/Documents/code/vllm/vllm/v1/sample/rejection_sampler.py)，无效位被 valid_mask 过滤 |
| **零 CPU-NPU 同步** | controller 决策不读设备张量；PLACEHOLDER 在 host pin_memory buffer 填充；接受核算仍走现有 GPU 修正 kernel |

整体数据流（一个 decode step）：
```
controller.latch_for_step()  →  k_active (CPU int, 本步锁定)
   ├─ scheduler: num_lookahead = k_active           （排程/KV 预留）
   ├─ proposer: draft 循环 range(k_active)           （只跑 k_active 步草稿前向）
   └─ runner verify: 草稿组装 padding 到 K_max       （host 侧填 PLACEHOLDER）
        → verify 前向 query=1+K_max（恒命中 FULL 图）
        → rejection sampler 用 num_draft=k_active（精度无损）
        → GPU kernel 修正 num_computed_tokens（async 无同步）
```

## 1. SpecLengthController 接口契约

### 1.1 类定义（新文件 `vllm_ascend/spec_decode/spec_length_controller.py`）

```python
class SpecLengthController:
    """动态投机长度控制器（CPU 侧纯整数状态，进程级单例）。
    红线：所有方法 O(1)、不读设备张量、不触发任何同步。
    """
    def __init__(self, k_max: int, k_init: int):
        assert 1 <= k_init <= k_max, "k_init 必须在 [1, k_max]"
        self._k_max = k_max                  # 预留上限（buffer/图/容量按此建）
        self._pending = k_init               # 待生效值（update 写这里）
        self._latched = k_init               # 本步锁定值（执行层读这里）

    @property
    def k_max(self) -> int:
        return self._k_max

    def update(self, k: int) -> bool:
        """热切换入口（API/config/第二阶段策略调用）。只置 pending，不立即生效。
        返回是否接受（越界拒绝）。线程安全：GIL 下整数赋值原子。"""
        if not (1 <= k <= self._k_max):
            logger.warning("spec_len %d 越界 [1,%d]，忽略", k, self._k_max)
            return False
        self._pending = k
        return True

    def latch_for_step(self) -> int:
        """调度步边界调用一次：把 pending 锁存为本步值，本步全程不变。
        这是切换"在调度步边界生效"的实现点（防线 1）。"""
        self._latched = self._pending
        return self._latched

    def get_active_len(self) -> int:
        """执行层每步读本步锁定值。O(1) CPU 读。"""
        return self._latched

    def decide(self, signals) -> int:
        """第二阶段占位：寻优策略。第一阶段直接 return self._pending。"""
        return self._pending
```

### 1.3 关键约束：K_max 必须驱动所有"按投机长度预留"的初始化

启动期把 `num_speculative_tokens` 的**有效值统一设为 K_max**，使下列预留全按 K_max（这样运行时 k_active 缩放无需重建）：
- proposer 三组 buffer list 按 K_max（[llm_base_proposer.py:208](file:///Users/linyi/code/Documents/code/vllm-ascend/vllm_ascend/spec_decode/llm_base_proposer.py)~[220](file:///Users/linyi/code/Documents/code/vllm-ascend/vllm_ascend/spec_decode/llm_base_proposer.py)）
- `uniform_decode_query_len = 1 + K_max`（[model_runner_v1.py:814](file:///Users/linyi/code/Documents/code/vllm-ascend/vllm_ascend/worker/model_runner_v1.py)）→ cos/sin、mc2、capture 全按 K_max
- dispatcher 注册 query=1+K_max 的 FULL 图 key（[cudagraph_dispatcher.py:211](file:///Users/linyi/code/Documents/code/vllm/vllm/v1/cudagraph_dispatcher.py)）

> 实现手法：让 `DynamicSpecConfig.enabled` 时，在 `check_and_update_config` 早期把 `speculative_config.num_speculative_tokens` 覆写为 `k_max`（其余代码无感知，自然全按 K_max 预留），把"动态"完全收敛到执行层的 `get_active_len()`。

## 5. 实现顺序（最小可验证增量）

1. **Controller + config**（改动 1/2/6）→ 单测：update/latch/越界拒绝。
2. **proposer range(k_active)**（改动 4）→ 验证 k_active 缩放草稿步数正确、精度对拍。
3. **runner padding**（改动 5）→ 验证 verify 恒命中图、PLACEHOLDER 不污染精度。
4. **scheduler patch**（改动 3）→ 验证 KV 预留按 k_active、边界锁存。
5. **热切换 API**（改动 7）→ 验证多 worker 一致切换、长稳。

每步独立可验证（goal-driven），不通过不进下一步。
