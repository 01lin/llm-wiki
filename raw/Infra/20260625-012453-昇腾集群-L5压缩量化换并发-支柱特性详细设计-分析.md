## 0. 一句话设计 + 一处对主文档的修正

> **设计**：压缩态 KV（compress_ratio=4）+ c8 量化 KV 降低单 token KV 字节 → 同显存装更多 block → 同 TPOT 红线下提升 max-num-seqs。属配置组合 + 精度验证，零 patch。
>
> **修正主文档 §3.5.1**（走读后发现作用域比初版更精确）：c8 不只作用于 DSA indexer K cache——`_allocate_int8_cache_tensor` 同时用于**主 k_tensor/v_tensor**（model_runner_v1.py:4053-4058）**和** indexer（:4072 `_allocate_sparse_c8_indexer_tensors`）。但 c8 带 per-token scale 开销（int8+fp16 scale 或 fp8+fp32 scale），**净压缩比 < 名义 2×**。

## 1. 已坐实的 KV 字节链路

| 环节 | 机制 | 证据 |
|------|------|------|
| 压缩态 KV | `use_compress`（gated on hf_config.compress_ratios） | model_runner_v1.py:270/352 |
| 压缩 slot mapping | get_compressed_pos_and_indices | :155/:1247 |
| c8 dtype | A5: float8_e4m3fn+fp32 scale；其他: int8+fp16 scale | :379-386 |
| c8 分配（主 KV） | `_allocate_int8_cache_tensor`(k_tensor/v_tensor) | :4053-4058 |
| c8 分配（indexer） | `_allocate_sparse_c8_indexer_tensors` | :3874/:4072 |
| 量化路径 | npu_dynamic_quant / cv_wkv.quantize（per-token scale） | dsa_v1.py:1503/1715 |
| 显存→block 换算 | num_blocks = sum_page_size_bytes // page_size_bytes | :4176 |

> **机制链坐实**：压缩/量化降 page_size_bytes → num_blocks 增 → 并发槽增。这是 L5 提并发的物理路径，非推测。

## 2. 修正后的 KV 字节账（比主文档 §3.5.1 更精确）

```
MLA latent bf16 基线：num_layers × (kv_lora_rank + qk_rope) × 2 bytes
  ≈ 61 × 576 × 2 ≈ 70 KB/token/序列（⚠️结构数为 V3/V4 公开参考值）

compress_ratio=4（✅坐实）：存储位置压缩，KV ≈ 70/4 ≈ 17.5 KB/token
c8（int8）叠加：bf16→int8 名义 2×，但 per-token scale(fp16) 开销：
  净 ≈ 1 byte 数据 + scale 分摊 ≈ bf16 的 0.55× （非 0.5×）
叠加后：70 KB × (1/4) × 0.55 ≈ 9.6 KB/token（vs 主文档初版 ~8.75 KB 略高）
```

> 修正点：c8 的 scale 开销使净压缩比从名义 8×（4×compress × 2×c8）降到 **实际 ≈7.3×**。差异不大，但**诚实账要算 scale**。

## 3. 换并发的显存边界（L5 倍率的真实约束）

```
D 节点 HBM 分配 ≈ 权重 + 激活/通信 buffer + KV cache
  KV 缩 7.3× 只放大"KV 占比"那部分的容量
设 baseline KV 占可用 HBM 的 r（经验 r≈0.4–0.6，需 E1 实测）：
  并发提升 ≈ 1 / (1 − r + r/7.3)
  r=0.5 → 1/(0.5+0.068) ≈ 1.76×
  r=0.6 → 1/(0.4+0.082) ≈ 2.07×
```

> **L5 倍率 1.5–2× 自洽**，且现在 r（KV 占 HBM 比）是**可实测参数**（E1），不再是拍脑袋。r 越大 L5 收益越大——长上下文 agentic 正是 r 大的场景。

## 4. 切入点与 patch 面积

| 组件 | 改动 | patch |
|------|------|-------|
| compress | additional_config / hf_config.compress_ratios | 0（配置） |
| c8 | ascend_config.enable_sparse_c8 | 0（配置） |
| max-num-seqs 上调 | recipe 参数（受 E1 显存边界约束） | 0（配置） |

> **L5 = 纯配置组合 + 精度验证，净新增 patch = 0**。三支柱里它最"白"，但精度风险最高（见遗留）。

## 5. 遗留问题（要求 1）

1. **c8 × compress 叠加精度无昇腾实测** — per-token dynamic quant 理论上误差可控，但叠加压缩态后对 DeepSeek-V4-Flash 输出质量的影响无数据。**这是 L5 的最大风险**（主文档 §3-L5、§6-5）。❓ 对应 §7-E1。
2. **r（KV 占 HBM 比）需实测** — 决定 L5 真实倍率，E1 扫描。❓
3. **c8 作用域的完整确认** — 走读见 int8 cache 用于主 KV + indexer，但是否所有层/所有模式都走 c8，还是仅 DSA 稀疏层，需进一步走读 `_reshape_kv_cache_tensors`(:4144) 确认。🟡 部分坐实
4. **TPOT 顶点** — 并发上调到何处 TPOT 破线，E0+E1 联合定。❓

## 6. 与验证矩阵衔接

L5 对应主文档 §7 **E1 实验**（compress/c8 四组合，同 TPOT 红线下 max seqs）。E1 单节点可测，直接坐实 r 和 L5 倍率，并验证精度（输出质量对比）。
