# Agentic 推理优化切入点 — 全景盘点与收益代入

> 用户已举例 KV/投机/调度三方面，要求以**推理系统 infra 优化专家视角**穷尽所有可能的优化切入点，先求全面，再用已有 case 数据代入估收益。
>
> 盘点方法（保证不漏）：沿**两个正交轴**系统扫描——① 请求全链路（接入→预填充→解码→产出）；② 引擎资源栈（计算/显存/通信/调度/存储）。两轴交叉覆盖，避免凭感觉列。
> 数据 case：SWE-agent（R=24 / ISL大 / ρ=14% / 工具返回79% / 截断26% / 解决率17%）、gaia2（fan-out5.3 / join67% / 并行度2.6 / 多app协同）。
> 标注：已在前文展开的标 ✓已展开，本文新增的标 ★新增。

## 0. 盘点框架：两轴扫描

```
        请求全链路 →   接入层    预填充     解码      产出
资源栈 ↓             (gateway)  (prefill)  (decode)  (output)
计算 (compute)         —        L1批处理   L2投机✓   —
显存 (memory/KV)       —        L3前缀✓    L4-KV✓    —
通信 (comm)            —        L5-PD      L6-EP/TP  —
调度 (schedule)        L7路由    L8批组织   L9逐出✓   —
存储 (cache/offload)   —        L10前缀库  L11分层    —
编解码 (tokenize)      L12       —          —        L13约束
```
12 个领域里 KV(L4)/投机(L2)/逐出(L9)/前缀(L3)已展开。**本文补全其余 8 个 ★新增领域**，并给全部收益代入。

## 一、完整切入点清单（按引擎层归类）

### 计算层（compute）

**1. 动态投机优化** ✓已展开（L2）—— 段类型自适应 draft 长度。

**2. ★ 自适应批处理 / Chunked Prefill 调参（L1）**
- **切入点**：agentic 请求 ISL 差异极大（SWE system 1218 + 工具返回历史可达数万 token vs 短轮次）。固定 chunk size 对长短混批不友好。
- **优化思路**：按 `osl_predicted` + `isl` 动态调 chunk 大小与 prefill/decode 配比，长短分离组批。
- **指标**：`osl_predicted`、`isl`、`segment_type`。

**3. ★ 约束解码与投机协同（L13）**
- **切入点**：SWE tool_call 段是 JSON/命令，gaia2 是 `app.function(args)` 结构化调用——这些位置 token 几乎确定。
- **优化思路**：结构化位置（schema 约束）的 token accept rate 接近 1，与投机解码协同 → 结构化段近乎免费生成。
- **指标**：`generation_format_constraint`（JSON schema）、`accept_rate_by_segment`。

### 显存层（memory / KV）

**4. KV Cache 管理** ✓已展开（L3前缀pin / L4换出/段压缩）。

**5. ★ KV 量化换并发（L4衍生）**
- **切入点**：910B3 单卡 64GB HBM 是硬约束，26% 截断证明 KV 压力。
- **优化思路**：对一次性工具返回历史段做更激进的低精度量化（如 2-bit KV / TurboQuant），用精度换并发——这些段不再参与生成，量化损失可接受。
- **指标**：`tool_return_token_ratio`、`one_shot_history_ratio`、`hbm_kv_utilization`。

**6. ★ Activation / 临时显存优化（L4衍生）**
- **切入点**：长 ISL（SWE 工具返回堆积）的 prefill activation 峰值显存大。
- **优化思路**：按 `isl` 预测 activation 峰值，长序列走 activation checkpointing / 分块，避免 OOM 截断。
- **指标**：`isl`、`hbm_kv_utilization`。

### 通信层（comm）

**7. ★ PD 分离弹性配比（L5）**
- **切入点**：agentic 负载 prefill/decode 比例随轮次波动（首轮大 prefill，后续多 decode）；多 agent 混部时比例更不稳。
- **优化思路**：聚合多 agent 的 `osl`/`isl`/阻塞画像，动态调 PD 实例配比，而非静态部署。
- **指标**：`osl_predicted`、`tool_blocking_ratio`、集群混合负载画像。

**8. ★ EP/MoE dispatch 与专家亲和（L6）**
- **切入点**：DeepSeek-V4/Qwen3.5-397B 是 MoE，agentic 同类任务（如都是 code agent）可能激活相似专家。
- **优化思路**：用 `task_id`/段类型做专家激活预测，优化 EP dispatch 的 all-to-all 通信（相似负载路由到同 EP 组减少跨卡）。
- **指标**：`task_id`、`segment_type`、专家激活分布。
- **谨慎**：泛化性存疑，需实测专家激活与 agent 类型的相关性。

**9. ★ 跨请求/跨 DC 的前缀传输（L5衍生）**
- **切入点**：gaia2 多 app 协同，共享前缀（工具定义）可跨实例复用。
- **优化思路**：高复用前缀的 KV 跨 PD 实例/跨节点传输复用（类 Prefill-as-a-Service），而非各自重算。
- **指标**：`prefix_reuse_rate`、跨实例命中。

### 调度层（schedule）

**10. 价值逐出 + 组完成调度** ✓已展开（L9）。

**11. ★ 任务级路由 / 亲和调度（L7）**
- **切入点**：multi-agent DAG 的子任务（gaia2 fan-out 5.3）若路由到不同实例，共享前缀/KV 无法复用。
- **优化思路**：同 `task_id` 的请求路由到同实例（亲和），最大化 KV/前缀复用；不同任务按负载均衡。
- **指标**：`task_id`、`session_id`、`prefix_reuse_rate`。

**12. ★ 预测式预热 / 投机预填充（L8）**
- **切入点**：agent 多轮，下一轮的稳定前缀（system+工具定义+已确定的对话历史）在本轮 decode 时已知。
- **优化思路**：decode 阶段用空闲算力预热下一轮稳定前缀的 KV（Dynamo `speculative_prefill` 思路），压多轮 TTFT。
- **指标**：`next_turn_stable_prefix`、`remaining_turns`。

**13. ★ 安全抢占 / 可中断调度（L9衍生）**
- **切入点**：agent 请求常可重试（幂等），但引擎不敢激进抢占。
- **优化思路**：agent 声明 `idempotent`/`interruptible` → 这类请求可被 kill 重来，抢占调度更灵活。
- **指标**：`request_idempotent`、`priority`。

### 存储层（cache / offload）

**14. ★ 分层 KV 存储调度（L11）**
- **切入点**：HBM→DRAM→NVMe 三级，agentic 长会话历史可下沉。
- **优化思路**：按 `remaining_turns`/`expected_idle_ms` 决定 KV 放哪一级（快结束/长阻塞的下沉到慢存储）。
- **指标**：`remaining_turns`、`expected_idle_ms`、访问频率。

**15. ★ 持久化前缀库 / 跨会话复用（L10）**
- **切入点**：同一 agent 框架的 system prompt + 工具定义跨会话、跨天高度稳定（SWE 单模板）。
- **优化思路**：把高频前缀的 KV 持久化到磁盘/共享存储，冷启动直接加载，免重算。
- **指标**：`prefix_reuse_rate`、前缀跨会话频率。

### 编解码层（tokenize）

**16. ★ Tokenize / Detokenize 优化（L12）**
- **切入点**：agentic 工具返回（大段 JSON/代码/日志）detokenize 开销不小；段 marker 打标在此层。
- **优化思路**：工具返回段批量/缓存 tokenize；detokenize 时顺带打 segment marker（服务 B-1 段DSL）。
- **指标**：`segment_type`、tokenize 耗时占比。

## 三、专家视角的关键判断

### 3.1 被忽略但高价值的"暗角"（前文没覆盖、值得补的）

- **#15 持久化前缀库**：实现简单（前缀 KV 落盘+冷启动加载）、收益确定（SWE system 单模板跨会话稳定）、独立于其它优化 → **应提到 P0**。前文只讲了运行时 pin，没讲跨会话/跨天的持久化，这是个低成本暗角。
- **#12 预测式预热**：利用 decode 空闲算力压下一轮 TTFT，agentic 多轮（R=24）场景收益累积可观，Dynamo 已有 speculative_prefill 通道可借。
- **#5 KV 量化换并发**：工具返回 79% 是一次性的，对它激进量化（2-bit）几乎无损生成质量 → 用精度换并发，是 agentic 负载特有的量化机会（普通负载不敢这么激进）。

### 3.2 按负载类型的优化地图

| 负载类型 | 判别特征 | 该主攻的切入点 |
|---|---|---|
| 单 agent 长会话（SWE类）| R大, fanout=1, 截断高 | 前缀pin/持久化库 + 价值逐出 + KV量化 + 预热 |
| multi-agent（gaia2类）| fanout>1, join多 | 组完成调度 + 任务亲和路由 + 跨实例前缀 |
| 结构化重输出 | tool_call/JSON占比高 | 约束解码协同 + 段DSL |
| 集群混部 | 多应用并发 | PD弹性配比 + 负载聚合自适应 |

### 3.3 完整性自检（infra 专家盘点是否有漏）

沿两轴扫描覆盖了：计算(批/投机/约束)、显存(KV/量化/activation)、通信(PD/EP/跨DC)、调度(逐出/路由/预热/抢占)、存储(分层/持久化)、编解码(tokenize/约束)。**16 个切入点覆盖请求全链路 × 资源栈全层**。

可能仍存在的盲区（诚实标注）：
- **能耗/功耗优化**（agentic 阻塞期降频）——未展开，910B3 功耗管理需硬件接口。
- **多模态 agent**（图像/工具截图）——本文 case 是纯文本 agent，多模态 KV 特性未覆盖。
- **容错/重算优化**（agent 长任务中断恢复）——偏可靠性，非纯性能。

## 四、收益代入的方法论说明

> 所有收益是**量级估算**，非精确值。代入逻辑：把 case 实测的 β/ρ/R/fanout 等代入 `收益=f(参数)`，给数量级 + 适用负载 + 优先级。精确值需：① 接 tokenizer 校准 token；② 真实墙钟阻塞分布；③ 实测 accept rate。优先级 P0-P3 按"收益确定性 × 实现成本"综合排，不是单看收益绝对值。

**一句话总结**：从三领域扩展到 **16 个切入点**，覆盖请求全链路×资源栈全层。其中 4 个被前文忽略的暗角（持久化前缀库/预测预热/KV量化换并发/任务亲和路由）值得补入近期清单，尤其 **#15 持久化前缀库实现简单、收益确定，应提到 P0**。
