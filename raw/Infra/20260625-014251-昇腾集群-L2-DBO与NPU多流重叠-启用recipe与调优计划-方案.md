## Task 2：开 DBO（L2，decode 侧 EP 通信重叠）

**Step 2.1 — 启用 + 阈值**
```bash
vllm serve $MODEL --served-model-name dsv4flash \
  --enable-dbo \
  --dbo-decode-token-threshold 32 \
  --dbo-prefill-token-threshold 512 \
  --speculative-config '{"num_speculative_tokens":3,"method":"deepseek_mtp"}'
  # bf16-only：无量化
```
**Step 2.2 — 验收（E4 dbo 分支）**
```bash
TPOT_SLO_CC=<E0红线> bash E0toE4脚本.sh e4 dbo_on
TPOT_SLO_CC=<E0红线> bash E0toE4脚本.sh e4 dbo_off
```
判据：`dbo_on/dbo_off` 吞吐比 ≈ 推导 1.43×（D 节点 EP64 收益最大）。

**遗留**：DBO×投机(MTP3) 同开稳定性——cascade 已被 DBO 禁(:2046)，DSA 路径不依赖 cascade，但需确认 MTP draft 在 microbatch 下正确。❓

## Task 3：开 NPU 多流重叠（L2'，DSV4 专项）

**Step 3.1 — DSV4 DSA 多流（最相关）**
```bash
--additional-config '{"multistream_dsv4_dsa_overlap":true,
                      "multistream_dsa_preprocess":true}'
```
**Step 3.2 — shared-expert / gate 多流（注意互斥）**
```bash
# ⚠️ multistream_overlap_shared_expert 与 enable_shared_expert_dp 互斥(:300-301)
# 二选一：若用 shared_expert_dp 则不能开此多流；否则可开
--additional-config '{"multistream_overlap_shared_expert":true,
                      "multistream_overlap_gate":true}'
```
**Step 3.3 — prefill 通信计算重叠（P 节点）**
```bash
# P 节点 recipe 追加
--additional-config '{"prefill_comm_compute_overlap":true}'
```
**Step 3.4 — 验收（E1 多流分支）**
```bash
bash E0toE4脚本.sh e1 ms_off
bash E0toE4脚本.sh e1 ms_dsa     # 仅 DSV4 DSA 多流
bash E0toE4脚本.sh e1 ms_all     # 全开（避开互斥项）
```
判据：逐项对比吞吐增量；ms_all/ms_off ≈ 1.2–1.4×（与 DBO 部分重叠，合并 §4 取 1.5–1.7×）。

## Task 4：DBO × 多流 联合调优

**Step 4.1 — 联合开 + 扫阈值**
```bash
# DBO + DSV4 多流 + prefill 重叠 联合
--enable-dbo --dbo-decode-token-threshold 32 \
--additional-config '{"multistream_dsv4_dsa_overlap":true,
                      "prefill_comm_compute_overlap":true}'
```
**Step 4.2 — 微批粒度调优**
```
扫 dbo_decode_token_threshold ∈ {16,32,64,128}：
  太小 → host 切分开销大；太大 → 重叠不足
找端到端吞吐最优点（A2/910B3 带宽下的甜点）
```
**验收**：联合配置吞吐 / 全关 ≈ 1.5–1.7×（推导目标）。
