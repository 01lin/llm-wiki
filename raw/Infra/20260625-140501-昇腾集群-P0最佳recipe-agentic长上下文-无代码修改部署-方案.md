## 4. 部署脚本 Recipe（P 节点 / D 节点）

> 基于官方 large_scale_ep recipe（[large_scale_ep.md:485](vllm-ascend/docs/source/user_guide/feature_guide/large_scale_ep.md)）+ 上述最佳参数，bf16 无量化。

### Prefill 节点（长上下文，prefill 主导）
```bash
vllm serve /models/DeepSeek-V4-Flash \
  --served-model-name dsv4flash \
  --data-parallel-size 2 --tensor-parallel-size 8 \
  --enable-expert-parallel \
  --max-model-len 524288 \
  --max-num-batched-tokens 16384 \
  --max-num-seqs 4 \
  --gpu-memory-utilization 0.9 \
  --enable-prefix-caching \
  --enable-chunked-prefill \
  --long-prefill-token-threshold 8192 \
  --speculative-config '{"num_speculative_tokens":3,"method":"deepseek_mtp"}' \
  --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_producer"}' \
  --additional-config '{
    "multistream_dsv4_dsa_overlap":true,
    "multistream_dsa_preprocess":true,
    "multistream_overlap_shared_expert":true,
    "prefill_comm_compute_overlap":false
  }'
```
> 注：prefill 节点理论上想开 `prefill_comm_compute_overlap`，但它与 `multistream_dsv4_dsa_overlap` 互斥（dsa_v1.py:1598）。**二选一须实测**（§6 存疑1）。此处先选 dsv4_dsa（覆盖面广）。

### Decode 节点（多轮 decode，大 EP）
```bash
vllm serve /models/DeepSeek-V4-Flash \
  --served-model-name dsv4flash \
  --data-parallel-size 64 --tensor-parallel-size 1 \
  --enable-expert-parallel \
  --max-model-len 524288 \
  --max-num-batched-tokens 256 \
  --max-num-seqs 28 \
  --gpu-memory-utilization 0.9 \
  --enable-prefix-caching \
  --speculative-config '{"num_speculative_tokens":3,"method":"deepseek_mtp"}' \
  --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_consumer"}' \
  --kv-events-config '{"enable_kv_cache_events":true,"publisher":"zmq","endpoint":"tcp://*:5557"}' \
  --additional-config '{
    "multistream_dsv4_dsa_overlap":true,
    "multistream_dsa_preprocess":true,
    "multistream_overlap_shared_expert":true,
    "eplb_config":{"dynamic_eplb":true}
  }'
```

## 5. 场景收益分析与可行性

| 配置项 | 场景亲和 | 收益方向（定性，代码逻辑支撑） | 可行性 |
|--------|---------|------------------------------|--------|
| prefix_caching（默认） | agentic 多轮 | 实例内历史前缀免重算 → 降 TTFT | ✅ 默认，零风险 |
| chunked_prefill（默认） | 512K 长上下文 | 长 prefill 不阻塞 decode → 稳 ITL | ✅ 默认 |
| multistream 三开 | 通用 | Cube∥Vector / 计算∥通信并行 → 提吞吐 | ✅ bf16 生效（CVwrapper 坐实），互斥已避 |
| ACL graph decode（默认） | decode 阶段 | 消 host launch 开销 | ✅ 默认 FULL_DECODE_ONLY |
| kv_events + connector | 跨实例多轮 | 跨实例前缀复用（**需消费端**） | 🟡 产出端坐实，消费端存疑（§6） |
| dynamic_eplb | 大 EP | 专家负载均衡，消热点 | ✅ 代码坐实可开 |

> **可行性总判**：§1（默认）+§2（多流）**完全可行、纯参数、零风险**——这是 P0 最稳收益。§3（跨实例）的 kv_events 产出可行，但**全局路由消费端是 L1 需构建项**，P0 阶段只能拿到"PD 分离 + 实例内前缀复用"，跨实例命中需后续 L1。

## 6. 遗留问题 / 存疑（硬性要求：代码无法 100% 判断处）

1. ❓ **prefill 节点 dsv4_dsa_overlap vs prefill_comm_compute_overlap 二选一** — 互斥坐实（dsa_v1.py:1598），但"prefill 段哪个收益大"代码无法判断，依上下文长度/SP 规模，**须实测**。
2. ❓ **kv_events 消费端** — 事件产出在 NPU 坐实，但"无代码修改下，example proxy 是否已消费事件做 prefix-affinity 跨实例路由"未走读确认。**理由**：examples/ 的 proxy 默认是 round-robin/load（前文 load_balance_proxy_server_example.py:352 _pick_server 走读见），**未见消费 kv_events 的全局前缀路由**——故 P0 跨实例命中能力存疑，倾向"需 L1 构建"。
3. ❓ **gate 与 shared_expert 同开行为** — 语义互斥无 raise（fused_moe.py:626 vs :748），P0 recipe 已规避（只开 shared_expert 不开 gate），但若想用 gate 需实测。
4. ❓ **MooncakeConnector 在 bf16 V4 的 PD 传输** — connector 类存在（mooncake_connector.py），但 bf16（非压缩态）KV 的传输路径是否最优，须实测（我 memory 记录 PD 传压缩态 KV 是 c4/c128，bf16 全量 KV 传输带宽压力更大）。🟡
5. ❓ **spec=3 MTP 与 multistream 同开稳定性** — 两者都动执行流，代码无冲突守卫但未见同开验证，**须实测**。
6. ❓ **max_num_seqs 28 在 512K bf16 的显存边界** — 官方 recipe 是 16k 上下文的值，512K 下 KV 占用大 7.9×，**28 可能超显存须下调**，依实测。

## 7. 一句话 P0 结论

- **零风险即得**：确认 prefix_caching + chunked_prefill + decode ACLgraph 默认开（别加 --enforce-eager），加 multistream 三开（dsv4_dsa + dsa_preprocess + overlap_shared_expert）。
- **需配置**：PD 分离 connector + kv_events + dynamic_eplb。
- **P0 拿不到的**：跨实例全局前缀命中（消费端是 L1 构建项，存疑2）——这是 P0→P1 的边界。
- **所有 ❓ 均为"收益标定/二选一/显存边界"类，须昇腾实测**，不影响"参数是否生效"的判断。
