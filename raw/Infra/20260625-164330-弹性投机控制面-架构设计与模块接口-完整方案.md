## 〇、定位（一句话）

> 动态投机不是动态改 gamma，而是一个 **RuntimeState 驱动的弹性投机控制面**：根据 batch 状态/模型结构/图约束/acceptance 反馈，统一决定 draft 长度，并保证 scheduler / proposer / verifier / sampler / graph dispatch 看到**同一份投机状态**。

**核心不变量**（贯穿全架构）：`active_D = active_k + 1` 必须在 query_start_loc / decode_token_per_req / spec_state_indices.size(-1) / graph_key / num_accepted 上界 中**同一轮取同值**。

## 三、关键模块设计

### 3.1 Strategy 层 —— SpecStrategyConfig（外挂配置）

```python
@dataclass
class SpecStrategyConfig:
    proposer_type: Literal["mtp","eagle","ngram","dflash","ssd"]
    draft_len_policy: Literal["static","batch_dynamic","req_dynamic","hybrid"]
    update_mode: Literal["static","step","window","feedback"]   # 投机更新模式（草稿图扩展3）
    graph_policy: Literal["full_first","fallback_gamma","piecewise"]
    max_draft_len: int        # 容量上界 = max_k
    min_draft_len: int
    attention_profile: Literal["gdn","dsa","mla","gqa","mha"]   # 本质是模型（扩展1）
    compatibility: CompatFlags  # async / rejection_sampler / multi_stream / aclgraph
```
- **扩展1（不同 attn = 本质是模型）** → `attention_profile`：GDN(Qwen) / DSA(DeepSeek V4)。
- **扩展2（投机方式）** → `proposer_type`：组合/单一投机策略。
- **扩展3（更新模式 静/动）** → `update_mode` + 投机头权重动态更新（见 §3.4）。

### 3.2 RuntimeState 层 —— SpecRuntimeState（Shape 单一事实源）

```python
@dataclass(frozen=True)
class SpecRuntimeState:
    active_k: int            # 本轮实际 draft 长度
    max_k: int               # 容量上界（buffer/graph capture/mamba blocks）
    # 派生（唯一来源）
    @property
    def active_D(self): return self.active_k + 1
    @property
    def graph_spec_k(self): return self.active_k
    # batch 信息
    num_reqs: int; num_tokens: int; uql: int
    # graph / fallback / 反馈
    graph_mode: str; graph_key: tuple | None
    fallback_hit: bool; accept_rate: float | None
```
**铁律**：draft_len / uql / pad / graph_key 只由此对象生成，其他模块**只消费不重推导**。

### 3.3 Execution 层 —— 按模型类型分两条适配链

| 模块 | 职责（只做一件事） |
|------|-------------------|
| SchedulerAdapter | 预留 speculative slot（用 max_k 容量） |
| ProposerAdapter | 生成 draft tokens + 输出真实 active_k |
| **GDN ExecAdapter** | spec_state_indices[:active_D]、conv/ssm state 按 accepted 提交、conv1d graph 分桶 |
| **DSA ExecAdapter** | spec_multiple→active_D、actual_seq_lengths、spec_slot_mapping[step] |
| GraphDispatcher | graph_key 带 spec_k；判 FULL/PIECEWISE/NONE |
| Verifier/Sampler | rejection sampling，回传 acceptance |

### 3.4 投机头权重动态更新（草稿图扩展3 + 用户需求）

- proposer 基座已有（§2.1），动态更新走 **`update_mode`** 声明 + proposer 的权重 reload 接口。
- ❓ **本地未坐实 proposer 权重热更新接口**——需确认 `AscendSpecDecodeBaseProposer` 是否支持运行时 reload draft 权重，或需新增。标存疑。

## 四、双模型路线的执行差异（架构图 ③-A / ③-B）

| | GDN（Qwen3.5/3.6）— 难 | DSA（DeepSeek V4 Flash/Pro）— 相对易 |
|---|---|---|
| KV | full-attn KV + recurrent state（conv+ssm） | HCS/CSA/SWA 稀疏压缩 KV（位置寻址） |
| state 提交 | **必须按 accepted 前缀提交 + conv 窗口滚动 + 回滚** | 无 recurrent state，逻辑长度不推进即不可见 |
| 静态投机变量 | `spec_q_per_seq=size(-1)`（ops/gdn.py:443） | `spec_multiple=num_spec+1`（mla_v1.py:851） |
| 风险点数 | 6（详见关联报告） | 2-3 |

> 架构层统一（三层），**差异收敛在 ExecAdapter 内部**——这正是"统一管理、避免 patch 扩散"的价值。

## 六、设计三原则（验收标准）

1. **Shape 单一事实源**：所有 draft_len/uql/pad/graph_key 只由 RuntimeState 生成。
2. **稳态零额外开销**：fixed_k = 静态 baseline 时命中 no-op fast path，**TPOT 不劣化**（动态投机优化的硬验收）。
3. **策略与执行解耦**：策略只决定 draft 长度，执行只消费 RuntimeState；**patch 覆盖最小**。

---

## 七、落地顺序

1. **新建 SpecRuntimeState（固定 fixed_k=3）** —— 对照 SGLang 同名实现。
2. **Runner/metadata 接入**：decode_token_per_req=active_D、num_decode_draft_tokens=active_k。
3. **分路线 ExecAdapter**：GDN（spec_state/conv/ssm/Mamba）；DSA（spec_multiple/seq_lens/slot_mapping）。
4. **GraphDispatcher**：graph_key 加 spec_k；GDN conv1d_params 按 (num_tokens, active_D) 分桶。
5. **GDN recurrent state 校验**（最难）：conv 窗口滚动 + ssm 索引 + block 对齐 + NULL 守卫。
6. **fixed_k=3 等价校验**（bit-exact + TPOT 不劣化）→ 接 Policy 层（batch_dynamic，对照 SGLang bs_entries）。
7. **扩展**：投机头权重动态更新 + 动态策略更新。

## 八、待核实/存疑

1. **proposer 权重热更新接口**（§3.4）：`AscendSpecDecodeBaseProposer` 是否支持运行时 reload draft 权重，未坐实。
2. **SGLang SpecRuntimeState 能否直接移植**：SGLang 是 protocol（adaptive_runtime_state.py:46 `AdaptiveSpecWorker(Protocol)`），vLLM 接入方式需适配 worker 结构。
3. **DSA indexer 跨 draft_step 累积**（关联报告存疑3）：决定 DSA 是否真"无 recurrent state"。
4. **Qwen3.6 / V4 Pro 结构差异**：本地无模型定义，3.6/Pro 若层配比/压缩档位有变需单独核对。
5. **acl_graph BatchDescriptor 扩展 spec_k 的兼容性**：现有 graph cache key 加字段是否影响非投机路径，需验证。
