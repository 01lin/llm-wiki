## 1. 定量场景设定（512K 上下文）

```
模型：DeepSeek-V4-Flash bf16，MLA latent=kv_lora_rank(512)+qk_rope(64)=576 dim/token/layer ⚠️V3/V4参考值
层数：61 ⚠️参考值          硬件：910B3，单卡 HBM 64GB ⚠️参考值
上下文：L = 512K = 524288 token
DSA：index_topk=512（✅坐实），SWA sliding_window=W（设 4096 ⚠️）
压缩：compressor_ratio=4（✅坐实，压缩层），SWA 层 ratio≤1
```

### 1.1 基线 KV 字节账（512K 单序列，已含压缩）

```
未压缩 MLA latent：61 层 × 524288 token × 576 dim × 2 byte ≈ 36.8 GB/序列  ← 不可行（>HBM）
基线已压缩（c4 压缩层 + SWA 层混合）：
  设半数层 c4 压缩(÷4)、半数 SWA(只留 W=4096)：
  c4 层：30.5 层 × 524288 × 576 × 2 / 4 ≈ 4.6 GB
  SWA 层：30.5 层 × 4096 × 576 × 2 ≈ 0.07 GB
  基线 KV ≈ 4.67 GB/序列（512K）
```

> **关键洞察（定量）**：基线压缩已把 512K 单序列 KV 从 36.8GB 压到 4.67GB（**7.9× 压缩**）。**这正是基线已吃掉的 L5/L7 收益**——所以这部分不能再算进 5–10×。

### 1.2 基线并发上限（定量）

```
D 节点可用 KV 显存 ≈ 64GB × 0.9(util) − 权重分摊(TP后) − 激活/通信buffer
  设权重+buffer 占 30GB → KV 可用 ≈ 27.6GB
基线 512K 并发数 = 27.6GB / 4.67GB ≈ 5.9 → 实际 ~5-6 并发/卡（512K 超长上下文）
```

> 512K 下基线并发极低（~6），**这恰是 5–10× 的空间来源**——不是降单序列 KV（已压到极限），而是**让这 6 个并发的算力/调度/路由不浪费**。

## 2. 基线外技术的定量收益推导

### 2.1 L1 全局前缀路由（最大杠杆，定量）

**场景**：agentic 多轮，512K 上下文里历史占比极高。

```
设单轮新增 x=8K，历史 H 增长到 504K（接近 512K 满）
命中率 = H/(H+x) = 504K/512K ≈ 98.4%
基线（无全局索引，N 实例 round-robin）：命中率 ≈ 1/N（历史恰在同实例概率）
  N=64 实例（官方 D DP64）→ 命中率 ≈ 1.6%
L1 后：命中率 → 98.4%（全局索引路由到持有实例）
prefill 重算量：基线每轮重算 504K token 的 prefill
  L1 后只算新增 8K → prefill 算量降 504K/8K = 63×（该请求）
```

**端到端吞吐增益（定量）**：

```
agentic 端到端时间 = TTFT(prefill) + decode_steps × TPOT
512K prefill 占比极高：设基线 TTFT:decode = 7:3（长上下文 prefill 主导）
L1 命中 98% → prefill 部分 ≈ 0.02× → 端到端时间 ≈ 0.7×0.02 + 0.3 = 0.314×
  → 吞吐 ≈ 1/0.314 ≈ 3.2×（仅 L1，512K agentic 多轮）
```

- **已有基础**：KVConnector 钩子 `get_num_new_matched_tokens`(mooncake_connector.py:1284) ✅、`KVCacheEvent` 事件源（ucm_connector.py:22）✅、可换 proxy(examples/)✅。
- **需重建**：全局前缀索引服务（消费 kv_events 聚合全局前缀树）。
- **可行性**：高（业界已落地，见下）。
- **工作量**：中（索引服务 ~1-2 人月 + proxy 改造 ~0.5 人月，无核心 patch）。
- **业界参考**：SGLang HiRadixTree（hiradix_cache.py）✅、Dynamo KVIndexer+KVPublisher ✅、cost 函数（dynamo router）。
- **L1 定量收益：512K agentic 多轮 ≈ 3.2×**。

### 2.2 L2 DBO（基线默认关，定量）

```
512K EP64 下 MoE all-to-all 通信占比（A2 带宽弱）：设 decode 单步通信:计算 = 4:6
DBO 重叠后通信隐藏 ≈ 70-80%：
  单步时间 baseline = 计算0.6 + 通信0.4 = 1.0
  DBO 后 = max(计算0.6, 计算0.6+通信0.4×0.25) ≈ 0.7
  → 1/0.7 ≈ 1.43×
```

- **已有基础**：`enable_dbo`(parallel.py:208，默认 False)✅、microbatch 切分(model_runner_v1.py:3309)✅。**代码完备，只是默认关**。
- **需重建**：无（开配置 + 调微批粒度）。
- **可行性**：极高（零开发）。
- **工作量**：极小（配置 + 调优 ~0.2 人月）。
- **业界参考**：SGLang TBO（two_batch_overlap.py）✅。
- **L2 定量收益：≈1.43×**。⚠️ 与 L4 投机叠加稳定性需验证(cascade 互斥, model_runner_v1.py:2046)。

### 2.3 L6 统一弹性（定量，按 P/D 漂移）

```
agentic 负载 P/D 比例动态漂移：设静态 4:4 配比下，
  prefill 重时段 P 排队、D 空转 30%；decode 重时段反之
  平均资源浪费 ≈ 25%（一侧空转）
L6 goodput 弹性消除该浪费：→ 1/(1−0.25) ≈ 1.33×
注：L1 命中后 prefill 锐减，P/D 漂移更剧烈 → L6 价值随 L1 放大
```

- **已有基础**：Scheduler 子类化（SchedulerDynamicBatch(Scheduler), scheduler_dynamic_batch.py:122）✅、EPLB(eplb_updator.py)✅。
- **需重建**：goodput 驱动的 P/D+EPLB 统一决策器 + 整机弹性编排（缺口已坐实）。
- **可行性**：中（业界有完整参考）。
- **工作量**：大（统一决策器 ~2-3 人月 + 整机弹性依赖 K8s 层 ~待定）。
- **业界参考**：**Dynamo Planner（完整落地）**——PREDICT(流量预测,local_planner.py:100)+PROPOSE(伸缩,:216)+TTFT 校正 ✅。
- **L6 定量收益：≈1.33×**。

### 2.4 L4 投机自适应（基线已有静态 MTP，增量部分）

```
基线静态 MTP-3：高负载时投机净收益转负（占算力）
自适应：高负载关投机省算力、低负载投满
  设 30% 时段高负载（自适应关投机省 ~15% 算力给吞吐）
  增量 ≈ 1.1-1.2×（仅自适应部分，非投机本身——投机已在基线）
```

- **已有基础**：proposer 全 ✅、接受率反馈(num_accepted_tokens, model_runner_v1.py:1017)✅。
- **需重建**：负载自适应控制器（B 层 hook）。
- **可行性**：中（业界自适应未明确落地）。
- **工作量**：小（hook 控制器 ~0.5 人月）。
- **业界参考**：SGLang 投机解耦(standalone_worker_v2)✅，但动态-k 未坐实 ❓。
- **L4 增量收益：≈1.1-1.2×**（注意：投机本身已在基线，这里只算自适应增量）。

## 3. 定量合成（修正基线版）

> ⚠️ **本节合成已被 bf16-only 最终版超越**：下式用 L2=1.43×（仅 DBO）；最终版把 DBO 与 NPU 多流重叠合并为 L2+L2'=1.5×，合成变为 `3.2 × 1.5 × 1.33 × 1.15 ≈ 7.3× → ×0.75 ≈ 5.5×`（上沿 10.4×）。**以 [[20260625-013625-昇腾集群-bf16only-NPU真实支持-双约束修正与重推导-方案]] §4 为准**。下式保留作推导轨迹。

```
基线外乘性叠加（512K agentic 多轮场景）：
  L1(3.2×) × L2(1.43×) × L6(1.33×) × L4自适应(1.15×)
  = 3.2 × 1.43 × 1.33 × 1.15 ≈ 7.0×

扣相互挤占（L1 命中后 prefill 算力释放被并发吃掉，L2/L6 部分重叠）：
  保守折算系数 0.75（比初版 0.5 更高，因基线已优化、漏桶更独立）
  7.0 × 0.75 ≈ 5.25×   → 落在 5–10× 下沿
乐观（L1 命中率高、长上下文 prefill 占比更高）：
  L1 可达 4× → 4 × 1.43 × 1.33 × 1.2 ≈ 9.1× → 5–10× 上沿
```

> **修正后结论**：在**已含 L3/L4-MTP/L5/L7 的强基线**之上，**5–10× 来自 L1（主）+ L2 + L6 + L4自适应**四项基线外技术。L1 是绝对主力（512K 长上下文下 prefill 占比极高，命中收益被放大到 3-4×）。**这比初版更可信**——因为不再重复计算基线已吃掉的收益。
