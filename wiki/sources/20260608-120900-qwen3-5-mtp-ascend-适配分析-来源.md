# Source: Qwen3.5 MTP 昇腾适配分析报告 (2026-03-30)

Status report on **Qwen3.5-397B-A17B-w8a8-mtp** (plus 122B-A10B, 35B-A3B) on Ascend 910B3/A2. Core thesis: the contradiction has shifted from "is MTP supported" to "is it stable, correct, and reliably TPOT-positive" - and on Ascend it is **not yet production-grade**.

## Repo division of labor
- **vLLM**: upstream SD framework, `qwen3_5_mtp` model type, algorithm evolution.
- **vLLM-Ascend**: actual landing of GDN/Mamba path, graph mode, MoE comm, PD-disaggregation, quantization fast path. Main battlefield for 397B optimization.
- Ascend MTP decode fast path only opens at `mtp_quantize == "w8a8_dynamic"` - gains bound to quantization. Custom `_forward_core` in `patch_qwen3_5.py` because `torch_npu` recurrent gated delta rule support is incomplete.

## Three risk clusters
1. **Graph mode**: `mtp+graph` cannot start (#7598, `KeyError: 60` under FULL_DECODE_ONLY); FullGraph padding/state pollution (#7506, a workaround).
2. **A2/910B3 MoE/EP comm**: `MoeDistributeDispatchV4` expert/card limit (#7553, `moeExpertNum 32 > 24`); EP startup failures (#7635); flashcomm v1 A2 bugs (#7683).
3. **PD-disaggregation stability**: nonzero-temperature request failures (#7604, release blocker); HCCL/FFTS timeouts at high concurrency (#7651); `min_tokens`/cache/scheduling params swing throughput up to 2x (#7653).

## Key landed win
vLLM-Ascend PR #7487 - prebuild GDN prefill chunk metadata off the hot path; better prefill-heavy/high-BS throughput and TTFT, acceptance stable. But "keeps the system from being dragged down by needless sync," not a full MTP fix.

## Lessons
- **Acceptance != end-to-end gain** (#36498: high acceptance, decode still slower than no MTP).
- Optimization must combine algorithm acceptance with operator stability and comm constraints.
- Short-term priority: GDN/Mamba path, FULL_DECODE_ONLY/graph compat, A2 MoE dispatch, hybrid KV cache/block_size/prefix cache, PD stability. Mid-term: upstream DSL.
