# Source: GLM5.1 MTP 投机性能优化方案

Internal optimization plan for **GLM5.1 MTP3** on Ascend 910B3 (vllm-ascend). Baseline: MTP3 acceptance ~50-60%, meaning ~1.5-1.8 tokens accepted per verify round - far from DeepSeek's reported 85-90% single-layer. Root cause diagnosed as **train-inference distribution shift** in MTP heads.

Performance model: `speedup = f(acceptance, K, draft cost, verify cost, system utilization)`.

## Algorithm levers (high value)
1. **FastMTP** (arXiv:2509.18362) - self-distillation train-test alignment; targets 75-85% acceptance, reported +82% / 2.03x. The root-cause fix.
2. **Multi-layer MTP** - use all MTP layers, not just layer 1 (vLLM #31204 RFC).
3. **L-MTP** (2505.15003) - skip-prediction (predict tokens 1/3/5), +22%.
4. **EARS** entropy-adaptive rejection - relax threshold under high target entropy; **GLM-4.7 MTP3 measured +14.6% throughput**; ~30 lines; code exists in vllm-ascend PR #7845 (closed on process grounds, not technical).
5. **DSL** dynamic speculation length (vLLM #36657 / PR #35301) - up to 3.6x; orthogonal to EARS.

## System levers
6. Multi-step graph merge (vllm-ascend #6077). 7. Zero-bubble async speculative (vLLM #29957, -2-3% TPOT). 8. `npugraph_ex` operator fusion. 9. Triton operator optimization (#5208). 10. Dynamic vocabulary compression (-30-50% draft latency).

## Advanced / long-term
11. Tree-based MTP (Sequoia 2402.12374, OPT-Tree 2408.04628). 12. EAGLE-3 style training (2503.01840). 13. MineDraft batch-interleaved (vLLM #38003). 14. QuantSpec (2502.20579, >90% acceptance, 2.5x). 15. Speculative-Speculative SSD (vLLM #36037).

## Projected gains
| Combo | Acceptance | Mean accept (MTP3) | Speedup |
|---|---|---|---|
| Baseline | 50-60% | 1.5-1.8 | 1.0x |
| +EARS+DSL (short) | 55-65% | 1.8-2.2 | 1.15-1.25x |
| +FastMTP (mid) | 75-85% | 2.5-3.0 | 1.5-1.8x |
| +Tree MTP (long) | 80-90% | 3.5-5.0 | 2.0-2.5x |

Recommended order: EARS (cheap, code exists) -> FastMTP -> DSL -> multi-layer -> L-MTP/tree.

## Counter-arguments
- Projected speedups are model-of-a-model estimates, not measured for GLM5.1 specifically.
- EARS/DSL gains are quality-controlled, not strictly lossless (relaxed verification).
- The DeepSeek 85-90% reference may not transfer to GLM5.1's architecture.

## Data gaps
- GLM5.1's actual MTP layer count is uncertain (gates the multi-layer lever).
- No measurement yet of the cache-vs-K tradeoff that DSL introduces.
