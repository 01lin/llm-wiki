# DSpark 投机解码深度分析

原始来源：`raw/Infra/Agentic_Inference/DSpark_analysis.md` + `raw/Infra/Agentic_Inference/20260628-191517-dspark-draft-confidence-e2e-deepdive-分析.md` + `raw/Infra/Agentic_Inference/20260628-201837-dspark-draft-head-structure-图文详解-分析.md`

论文：《DSpark: Confidence-Scheduled Speculative Decoding with Semi-Autoregressive Generation》（DeepSeek-AI & 北大，2026-06）  
仓库：https://github.com/deepseek-ai/DeepSpec（MIT，含 DSpark/DFlash/Eagle3 三种 draft）

## 一句话定位

DSpark = **DFlash 并行骨干**（高吞吐 draft）+ **轻量顺序头**（注入 block 内 token 依赖，缓解 suffix decay）+ **置信度头**（估计逐位置接受概率）+ **硬件感知前缀调度器**（按系统负载动态截断验证长度）。

## 性能数据

vs MTP-1 基线（同吞吐）：V4-Flash 每用户生成速度 +60~85%，V4-Pro +57~78%  
离线 accepted length：vs Eagle3 +26.7~30.9%，vs DFlash +16.3~18.4%（Qwen3-4B/8B/14B）

## 模型结构（5 个盒子）

```
① Target 模型（冻结）：抽第 1/9/17/25/33 层 hidden（5份）拼成 context
   ↓
② Draft 骨干（5 层迷你 Qwen3）：fc 压 5→1份 context，输入 [anchor, MASK×6]
   Q=draft，K/V=[target_context|draft] 拼接；块内双向 mask；输出 h₁..h₇
   ↓
③ lm_head（冻结共享）：h_k → 基础候选分 U_k [1,7,词表]
   ↓
④ Markov 头：串行接龙补依赖 B_k = W1[x_{k-1}]@W2（低秩 r=256）
   for k: x_k ~ softmax(U_k + B_k(x_{k-1}))
   ↓
⑤ 置信度头：Linear(2816→1)，c_k = sigmoid(w^T[h_k; W1[x_{k-1}]])
```

Qwen3-4B 配置：`block_size=7, num_draft_layers=5, target_layer_ids=[1,9,17,25,33], markov_rank=256`

## 推理一轮 e2e 数据流

```
① 并行骨干 forward_dspark_draft_block   → block_hidden h₁..h₇
② base logits  U_k = lm_head(h_k)
③ Markov 串行  for k: x_k ~ softmax(U_k + W1[x_{k-1}]@W2)   （串行，但每步极廉价）
④ 置信度+截断  ℓ = 第一个 sigmoid(c_k)<threshold 的位置
⑤ Target 验证  rejection sampling（cumprod 保证前缀性，无损）
每轮净产出 = accepted + 1 token（接受前缀 + bonus/残差）
```

**关键细节**：
- draft KV 每轮即用即裁（`crop(start)`），不跨轮累积
- 截断为 0 时退化纯自回归，仍前进 1 token
- 累积生存概率 `a_j=cumprod(c_k)` 只在离线诊断用，在线截断只看单点 `c_k<threshold`

## 投机长度的粒度

| 层面 | 结论 |
|------|------|
| 开源 eval | bsz=1 单请求，谈不上层级（assert 强制）|
| 论文生产调度（Algorithm 1）| request-level，per-request `ℓ_r` + per-token `(r,j)` 粒度 |

DSpark 与 DSL 的分水岭：DSL 是 step-level 全局统一长度；DSpark 生产是 request-level 逐请求各自 `ℓ_r`，按累积生存概率 `a_{r,j}` 贪心 admit。

代价：request-level 变长 → 需变长 query kernel（flatten token + marker tensor），这是 Ascend 移植的 P0 工作量。

## 开源边界

生产级 hardware-aware scheduler（Algorithm 1）、ZOS 异步、HAI-LLM 引擎集成**均未开源**，只在论文描述。开源代码只实现了离线诊断评估（bsz=1）。

## Counter-arguments

- Markov 顺序头的串行循环（γ 步）在图模式下需显式处理，否则触发 recompile；Ascend torchair 移植难度高
- 硬件感知调度器未开源，外部复现需逆向工程，风险大
- suffix decay 问题在高 temperature 场景下 Markov 修正效果尚无大规模验证

## Data gaps

- DSpark 在 Ascend 910B3 上的移植可行性（变长 kernel、双 KV cache 异节奏推进）尚未实测
- 生产调度器（Algorithm 1）与 vllm-ascend 调度架构的具体接口对接方案未设计
- DSpark 对 MoE 模型（DeepSeek-V4/Qwen3.5-397B）的 accepted length 数据不完整
