# EAGLE / EAGLE-3

**EAGLE** is a [[20260608-120000-speculative-decoding-概念]] drafter that generates candidates from a small auxiliary network combining the target model's **hidden states** with **draft token embeddings** (rather than tokens alone). It needs trained EAGLE weights. **EAGLE-3** (NeurIPS 2025, arXiv:2503.01840) uses tri-layer feature fusion plus a training-time test strategy that simulates inference-time behavior, reportedly 3-6.5x speedup with +38% batch throughput.

In vLLM, `eagle.py` is the core and largest spec-decode file (>500 lines): it implements `SpecDecodeBaseProposer`, supports tree attention (`tree_attn`), CUDA Graph, and TP + draft-parallel strategies. EAGLE-3 uses combined auxiliary + normal hidden states.

On Ascend, the `AscendEagleProposer` handles EAGLE/EAGLE-3 **and** [[20260608-121100-mtp-multi-token-prediction-概念]] (MTP routes through the EAGLE path), so all three share NPU-optimized tree attention and ACL Graph. EAGLE-3-style training is a proposed lever to fix MTP's train-inference gap (see [[20260608-120800-glm5-1-mtp-投机性能优化方案-来源]]).

## Counter-arguments / Data gaps

- Requires separately trained weights, unlike MTP (built-in) - extra training cost and storage.
- No direct EAGLE-3 vs MTP comparison on identical model/hardware in these sources.
- Ascend EAGLE-3 listed on the Q1 2026 roadmap (#5318) but maturity unconfirmed.
